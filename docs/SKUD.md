# СКУД Hikvision: регистрация с сайта

Сайт ставит задания в очередь (`SkudJob`), локальный агент в лицее (`agent.js` + `agent-skud.js`)
забирает их и записывает людей на терминалы по ISAPI. Сайт терминалов напрямую не видит.

## Что умеет

| Возможность | Где |
|---|---|
| Фото: камера, файл, drag&drop, вставка Ctrl+V; проверка резкости, света, размера, лица (если браузер умеет `FaceDetector`) | `/skud-register.html` |
| Массовая загрузка: имя файла = поименный № или ИНН | там же, «Массовая загрузка» |
| Ссылка/QR, чтобы студент снял себя сам; куратор или админ принимает фото | кнопка «Ссылка» |
| Согласие на обработку биометрии (отметка сохраняется) | при отправке фото |
| Сводка по группам, кого нет в СКУД, выгрузка в Excel | `/skud-status.html` |
| Состояние терминалов, уведомления в Telegram об отключении | вкладка «Терминалы» |
| Восстановление истории посещаемости с терминалов за выбранные даты (без дублей, без уведомлений родителям; нужен новый agent.js + agent-skud.js) | вкладка «Терминалы» |
| Сверка терминалов с базой, удаление лишних | вкладка «Сверка» |
| Журнал действий (хранится год) | вкладка «Журнал» |
| Удаление с терминалов (кнопка и автоматически при удалении студента/группы) | регистрация |
| Преподаватели, мастера, гости: временная ссылка-анкета, одобрение админом | `/skud-staff.html` |
| Администрация: отдельная категория (номера 6000001+), своя вкладка в учёте посещаемости `/staff` (был/не был, часы, табель и лист в Excel) | `/skud-staff.html`, `/staff` |
| Массовая загрузка преподавателей, мастеров, администрации из Excel (ФИО, дата рождения, ИНН, номер необязательно): предпросмотр, пропуск дублей, шаблон | `/skud-staff.html` |
| Срок пропуска (гости по умолчанию 30 дней, у остальных можно задать) | ссылка сотрудника / фото студента |
| Роли: админ видит всё, куратор только свои группы | везде |

Номера сотрудников назначаются сами: администрация 6000001+, преподаватели 7000001+, мастера 8000001+, гости 9000001+. Номер из Excel (4-й столбец) тоже принимается.

## Установка

1. **Сайт (Render).** Задайте переменные из `.env.example`, особенно `SESSION_SECRET`. Сессии подписываются, поэтому
   после обновления все войдут заново.
2. **Агент (ПК в лицее).** Положите рядом `agent.js` и `agent-skud.js`, в `.env` задайте `AGENT_API_KEY`, `HIK_USER`, `HIK_PASS`
   (см. `agent.env.example`), `npm i digest-fetch dotenv`, перезапустите агента.
3. Откройте `/skud-status.html`, вкладка «Терминалы»: через минуту там появятся три терминала.

## Что проверено, а что нет

Автотесты (`npm test`) гоняют API сайта на БД в памяти и имитации терминала с Digest-авторизацией.
На реальных терминалах и настоящей MongoDB пока не проверялись:

- удаление (`UserInfo/Delete`, запасной `UserInfoDetail/Delete`), список (`UserInfo/Search`) и счётчик (`UserInfo/Count`) зависят от прошивки;
- `FaceDetector` есть не во всех браузерах (без него остаются проверки резкости, света и размера).

Если сверка или удаление ругаются, пришлите текст ошибки из окна агента: это настраивается одной строкой в `agent-skud.js`.
